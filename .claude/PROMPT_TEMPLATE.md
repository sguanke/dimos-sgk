# 从零开始生成多智能体配置的提示词模板

## 🎯 完整提示词（一次性生成所有配置）

```
我想为一个[项目类型]项目创建完整的多智能体开发工作流配置。

## 项目背景
- **硬件平台**: [例如：宇树Go2机器狗]
- **开发框架**: [例如：dimos分布式机器人操作系统]
- **编程语言**: [例如：Python 3.10+]
- **项目目标**: [例如：实现人员跟随功能，使用计算机视觉检测和跟踪指定人员，控制机器人保持安全距离跟随]

## 技术栈要求
- **视觉处理**: [例如：YOLOv8人员检测 + DeepSORT跟踪]
- **运动控制**: [例如：PID控制器 + DWA局部路径规划]
- **定位方法**: [例如：里程计 + IMU融合]
- **通信方式**: [例如：ROS2 Humble]
- **安全要求**: [例如：100ms紧急停止，0.3m最小安全距离]

## 多智能体架构要求

### 1. 实现智能体（并行开发）
请将实现工作拆分为以下专门的智能体：
- **感知智能体**: 负责[具体模块，例如：视觉检测和跟踪]
- **导航智能体**: 负责[具体模块，例如：运动控制和路径规划]
- **定位智能体**: 负责[具体模块，例如：位姿估计和建图]
- **安全智能体**: 负责[具体模块，例如：安全监控和紧急处理]

### 2. 集成智能体
- 负责整合所有模块
- 创建框架集成层
- 生成项目入口点

### 3. 测试智能体（并行开发）
- **单元测试智能体**: 为所有模块编写单元测试，目标覆盖率>80%（安全模块100%）
- **集成测试智能体**: 测试模块间交互和数据流
- **仿真测试智能体**: 端到端场景测试

### 4. 自动测试-修复智能体（循环执行）
- **测试运行智能体**: 自动运行所有测试并收集详细失败报告
- **调试智能体**: 智能分析测试失败的根本原因，生成修复策略
- **修复智能体**: 自动修复常见问题（初始化错误、类型转换、边界检查等）
- **验证智能体**: 验证修复效果并检测回归，如有回归自动回滚

## 工作流配置要求

### 隔离策略
- 实现智能体使用**git worktree隔离**，每个智能体在独立分支工作
- 集成/测试/审查智能体在主分支工作，可以访问worktree中的代码

### 自动提交和推送
- 每个智能体完成后**自动提交代码**
- **推送到当前分支**（不要硬编码分支名）
- 提交信息要清晰描述改动内容

### 日志系统
- 所有关键步骤输出到**控制台和日志文件**
- 日志文件保存在`.claude/logs/`，带时间戳
- 记录智能体执行时间、Git操作、错误信息

### 自动测试-修复循环
- 最多迭代**6次**
- 所有测试通过时**提前退出**
- 支持**条件执行**（只在有失败时运行修复）
- 自动检测**回归并回滚**

## 需要生成的配置文件

请生成以下完整的配置文件结构：

### 1. 核心配置文件
- **`CLAUDE.md`**: 项目架构和开发规范主文档
  - 技术栈定义
  - 模块职责划分
  - 代码质量标准
  - 安全要求
  - 开发命令
  - 冲突解决规则

- **`orchestrator.py`**: Python编排器
  - 解析workflow.yml并执行
  - 支持循环控制和条件执行
  - 自动提交和推送（推送到当前分支）
  - 双输出日志系统（控制台+文件）
  - 错误处理和重试机制

- **`requirements.txt`**: Python依赖
  - 编排器依赖（pyyaml等）

### 2. .claude/目录配置文件

- **`.claude/workflow.yml`**: 标准工作流定义
  - 6个阶段：planning, implementation-parallel, implementation-integration, testing, review, final-integration
  - 8个智能体配置
  - 依赖关系定义
  - 自动提交配置

- **`.claude/workflow_with_autofix.yml`**: 增强版工作流（含自动测试-修复）
  - 包含标准工作流的所有内容
  - 新增auto-test-and-fix阶段（4个智能体，最多6次迭代）
  - 循环控制配置
  - 条件执行配置

- **`.claude/agent_prompts.md`**: 每个智能体的详细实现指令
  - 每个智能体200+行详细指南
  - 输入输出定义
  - 代码质量要求
  - 配置文件模板
  - 测试策略
  - 禁止事项

- **`.claude/architecture.md`**: 系统架构可视化文档
  - 智能体工作流程图
  - 模块依赖关系图
  - 数据流图
  - 隔离策略说明

- **`.claude/auto_fix_design.md`**: 自动测试-修复系统技术设计
  - 系统架构
  - 4个智能体详细定义
  - 状态文件格式
  - 智能修复策略
  - 循环控制逻辑

- **`.claude/AUTO_FIX_GUIDE.md`**: 自动测试-修复系统使用指南
  - 快速开始
  - 每个智能体详解
  - 修复示例（修复前后对比）
  - 故障排除
  - 最佳实践

### 3. 顶层文档

- **`README.md`**: 项目主文档（中文）
  - 项目概述
  - 多智能体工作流介绍
  - 快速开始指南
  - 项目结构
  - 配置文件说明
  - 工作流阶段详解
  - 开发命令
  - 故障排除

## 配置要求细节

### Git提交逻辑
- 获取当前分支名：`git branch --show-current`
- 推送到当前分支：`git push -u origin <current_branch>`
- 检测detached HEAD状态，跳过推送
- 不要硬编码分支名

### 日志格式
- 控制台：简洁格式，只显示消息
- 文件：详细格式，包含时间戳和级别
- 记录内容：智能体启动/完成、Git操作、错误、性能指标

### 自动修复策略
支持以下问题类型的自动修复：
- 未初始化的变量 → 添加初始化检查
- 类型转换错误 → 添加类型转换
- 缺少错误处理 → 添加try-except
- 边界检查缺失 → 添加边界检查
- 简单逻辑错误 → 修正算法
- 导入路径错误 → 修正import语句

### 状态文件
所有状态文件保存在`.claude/state/`：
- 智能体输出：`<agent-name>.json`
- 测试结果：`test_results.json`, `test_failures.json`
- 问题分析：`problem_analysis.json`
- 修复记录：`fixes_applied.json`
- 验证结果：`verification_results.json`
- 覆盖率报告：`coverage.json`
- HTML报告：`test_report.html`

## 输出要求

1. **不要生成实际代码**，只生成配置文件
2. 所有文档使用**中文**
3. 配置文件要**自洽**，相互引用正确
4. 提供**完整的使用说明**
5. 包含**故障排除指南**
6. 提供**示例输出**展示工作流执行效果

## 验证要求

生成配置后，请：
1. 检查所有文件路径是否一致
2. 检查智能体依赖关系是否正确
3. 检查prompt是否正确引用agent_prompts.md
4. 检查Git提交逻辑是否推送到当前分支
5. 检查循环配置是否正确（6次迭代，提前退出）
6. 检查条件执行配置是否正确

请生成完整的配置文件结构。
```
